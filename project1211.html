미로 탐색에서 너비 우선 탐색(BFS)과 깊이 우선 탐색(DFS)의
경로 길이와 방문 칸 수 비교

Comparing Path Length and Visited Cells of BFS and DFS in Grid Mazes

전북과학고등학교 1학년 · 1211 윤성일
정보과학 3단원 「알고리즘」 소논문

국문 초록

정보과학 시간에 BFS는 큐, DFS는 스택을 이용한다고 배웠고, BFS는 최단 경로를 찾는다고 정리하였다. 이 설명이 실제 미로에서 어떻게 나타나는지 확인하기 위해 파이썬으로 미로를 만들고 두 알고리즘을 같은 조건에서 비교하였다. 길이 하나뿐인 완전 미로와, 벽을 10% 더 허물어 길이 여러 개 생긴 고리 있는 미로를 한 변 21~161칸의 네 가지 크기로 10개씩 만들어, 도착할 때까지 방문한 칸 수와 찾은 경로 길이를 측정하였다. 완전 미로에서는 두 알고리즘이 항상 같은 경로를 찾았고, DFS가 더 적은 칸을 방문하였다. 고리 있는 미로에서는 BFS가 항상 최단 경로를 찾았지만 161×161 미로에서 전체 길 칸의 99.1%를 방문하였다. DFS는 24.1%만 방문했지만 찾은 경로가 최단 경로의 3.96배였다. 이를 통해 두 알고리즘은 어느 한쪽이 항상 좋은 것이 아니라, 최단 경로가 필요한지 빠르게 아무 경로나 찾으면 되는지에 따라 골라야 한다는 것을 확인하였다.

주제어: 너비 우선 탐색, 깊이 우선 탐색, 큐, 스택, 미로, 최단 경로

Abstract

This study compares breadth-first search (BFS) and depth-first search (DFS) on grid mazes generated in Python. Two maze types were used: perfect mazes with exactly one route between any two cells, and looped mazes made by removing an extra 10% of inner walls. For each of four sizes (21 to 161 cells per side), ten mazes were generated and the number of cells visited before reaching the goal and the length of the found path were measured. In perfect mazes both algorithms always found the same path, and DFS visited fewer cells. In looped mazes BFS always found the shortest path but visited 99.1% of all open cells in the 161×161 case, while DFS visited only 24.1% but returned a path 3.96 times longer than the shortest one. The results show that the choice between BFS and DFS depends on whether the shortest path is required.

Keywords: breadth-first search, depth-first search, queue, stack, maze, shortest path

Ⅰ. 서론

1. 연구 동기

2단원에서 큐(FIFO)는 BFS, 스택(LIFO)은 DFS와 연결된다고 배웠고, 3단원에서는 탐색 기반 알고리즘과 알고리즘의 성능을 배웠다. 수업에서는 "BFS는 최단 경로를 찾는다"고 정리했는데, 그렇다면 DFS로 찾은 길은 최단 경로보다 얼마나 긴지, 대신 DFS가 얻는 이점은 무엇인지 궁금해졌다. 그래서 미로를 직접 만들어 두 알고리즘을 같은 조건에서 돌리고 결과를 숫자로 비교해 보기로 하였다.

2. 연구 문제

연구 문제 1. 미로의 구조(길이 하나인 미로 / 길이 여러 개인 미로)에 따라 BFS와 DFS가 찾은 경로의 길이는 어떻게 달라지는가?
연구 문제 2. 도착점을 찾을 때까지 방문한 칸 수는 어느 알고리즘이 더 적으며, 미로 크기에 따라 어떻게 변하는가?

Ⅱ. 이론적 배경

1. 미로를 그래프로 보기

격자 미로에서 지나갈 수 있는 칸 하나를 정점(V), 상하좌우로 붙어 있는 칸 사이의 연결을 간선(E)으로 보면 미로는 그래프가 된다. 따라서 2단원에서 배운 그래프 탐색을 그대로 적용할 수 있다.

2. BFS와 DFS

구분BFS (너비 우선 탐색)DFS (깊이 우선 탐색)
자료구조큐 — 먼저 넣은 칸을 먼저 꺼냄스택 — 나중에 넣은 칸을 먼저 꺼냄
탐색 모양출발점에서 거리 1인 칸을 모두 본 뒤 거리 2인 칸을 보는 식으로 물결처럼 퍼짐한 방향으로 끝까지 들어갔다가 막히면 되돌아옴
최단 경로항상 찾음 (가중치 없는 그래프)보장하지 않음
시간 복잡도둘 다 O(V+E) — 각 칸을 최대 한 번씩만 방문

BFS가 최단 경로를 찾는 이유는 가까운 칸부터 차례로 보기 때문에, 도착점에 처음 닿았을 때의 경로가 곧 가장 짧은 경로가 되기 때문이다(Moore, 1959). 두 알고리즘의 시간 복잡도는 같으므로(Cormen et al., 2022), 실제 차이는 칸을 보는 순서에서 생긴다.

Ⅲ. 연구 방법

1. 미로 생성

종류만드는 방법특징
완전 미로무작위로 벽을 뚫으며 나아가는 방식(recursive backtracker, Buck, 2015)을 스택으로 구현모든 칸 사이에 길이 정확히 하나 (고리 없음)
고리 있는 미로완전 미로를 만든 뒤 칸과 칸 사이 내부 벽의 10%를 무작위로 추가로 허묾출발점에서 도착점까지 길이 여러 개

미로 크기는 한 변 21, 41, 81, 161칸(벽 포함)이고, 출발점은 왼쪽 위 (1, 1), 도착점은 오른쪽 아래 (n−2, n−2)이다. 크기와 종류마다 시드(seed) 0~9로 미로 10개를 만들어 평균을 냈다. 시드를 고정했기 때문에 코드를 다시 실행하면 같은 미로가 만들어져 결과를 재현할 수 있다.

2. 비교한 알고리즘과 측정값

BFS와 DFS를 하나의 함수로 구현하고, 칸을 꺼낼 때 popleft()(큐)를 쓰면 BFS, pop()(스택)을 쓰면 DFS가 되도록 하였다. 나머지 코드는 완전히 같으므로 두 알고리즘의 차이는 자료구조 하나에서만 생긴다.

측정값의미
방문한 칸 수도착점을 찾을 때까지 큐·스택에서 꺼낸 칸의 수. 전체 길 칸 대비 비율도 계산
경로 길이출발점부터 도착점까지 찾은 경로의 칸 수 (출발·도착 칸 포함)

실험 환경은 Python 3이며, 외부 라이브러리 없이 random, collections.deque만 사용하였다.

Ⅴ. 논의

1. BFS가 미로를 거의 다 방문한 이유

도착점이 출발점에서 가장 먼 구석에 있기 때문이다. BFS는 가까운 칸부터 차례로 보므로, 도착점보다 가까운 칸을 모두 본 다음에야 도착점에 닿는다. 고리 있는 미로는 지름길이 생겨 대부분의 칸이 도착점보다 가까워지므로, 결국 거의 모든 칸을 방문하게 된다. 최단 경로를 보장받는 대가로 많은 칸을 확인해야 하는 셈이다.

2. DFS의 경로가 길어진 이유

DFS는 처음 들어간 방향으로 끝까지 가다가 도착점을 만나면 바로 멈춘다. 고리 있는 미로에서는 도착점까지 가는 길이 여러 개인데, DFS는 그중 처음 만난 길을 돌려줄 뿐 그 길이 짧은지는 따지지 않는다. 미로가 클수록 돌아가는 길도 길어지므로 최단 경로와의 차이가 커졌다.

3. 실험에 영향을 준 조건

코드에서 이웃을 상·하·좌·우 순서로 스택에 넣기 때문에, 가장 나중에 넣은 오른쪽과 아래가 먼저 탐색된다. 도착점이 오른쪽 아래에 있어서 이 순서가 DFS에 유리하게 작용했을 가능성이 있다. 반면 BFS는 거리 순서로 탐색하므로 이웃 순서의 영향을 거의 받지 않는다.

Ⅵ. 결론 및 한계

1. 결론

첫째, 길이 하나뿐인 미로에서는 BFS와 DFS가 같은 경로를 찾았고, DFS가 더 적은 칸을 방문하였다. 둘째, 길이 여러 개인 미로에서는 BFS만 최단 경로를 찾았으며, DFS의 경로는 최대 3.96배 길었다. 셋째, 그 대신 BFS는 최대 99.1%의 칸을 방문하여 DFS(24.1%)보다 훨씬 많은 칸을 확인해야 했다. 따라서 가장 짧은 길이 꼭 필요하면 BFS를, 길이 있는지 빨리 확인하기만 하면 될 때는 DFS를 쓰는 것이 알맞다. 수업에서 배운 "큐는 BFS, 스택은 DFS"라는 내용이 실제로 이렇게 다른 결과를 만든다는 것을 숫자로 확인하였다.

2. 한계와 후속 연구

  • DFS의 이웃 순서가 도착점 방향과 맞아 DFS에 유리했을 수 있다. 이웃 순서를 바꾸거나 무작위로 섞어 다시 실험할 필요가 있다.
  • 실행 시간과 메모리 사용량(큐·스택에 동시에 들어 있는 칸 수)은 측정하지 않았다.
  • 미로 크기는 4가지, 크기별 미로는 10개로 표본이 많지 않다.
  • 후속 연구로, 도착점 방향을 미리 고려하는 A* 탐색과 비교해 보고 싶다.

Ⅶ. 세부능력 및 특기사항 (작성 참고용)

이 부분은 제출용이 아니라 참고용 초안입니다. 실제로 내가 직접 이해하고 해 본 내용만 남기고, 내 말로 고쳐 써야 합니다.

큐와 스택을 배운 뒤 BFS가 최단 경로를 찾는다는 설명을 직접 확인하고 싶어 미로 탐색 실험을 설계하였습니다. 파이썬으로 길이 하나인 완전 미로와 길이 여러 개인 고리 있는 미로를 크기별로 만들고, BFS와 DFS를 하나의 함수에서 popleft()와 pop()만 바꿔 구현하여 자료구조의 차이만 비교되도록 하였습니다. 고리 있는 미로에서 BFS는 항상 최단 경로를 찾았지만 161×161 미로에서 전체 칸의 99.1%를 방문했고, DFS는 24.1%만 방문했지만 경로가 최단 경로의 약 4배였다는 결과를 얻었습니다. 이를 통해 두 알고리즘의 시간 복잡도는 같더라도 탐색 순서에 따라 결과가 크게 달라지며, 문제의 목적에 맞게 알고리즘을 골라야 한다는 것을 이해하였습니다. 또한 이웃을 보는 순서가 DFS에 유리하게 작용했을 수 있다는 한계를 스스로 찾아 후속 실험 방향을 제시하였습니다.

부록 A. 실험 코드 (maze_easy.py)

"""
미로에서 BFS와 DFS 비교 (쉬운 버전)
1211 윤성일 - 정보과학 3단원 소논문

실행: python maze_easy.py
"""
import random
from collections import deque

WALL, ROAD = 1, 0
MOVES = [(-1, 0), (1, 0), (0, -1), (0, 1)]  # 상, 하, 좌, 우


def make_maze(n, seed, loop=False):
    """n x n 미로 만들기 (n은 홀수). loop=True면 벽을 10% 더 뚫어서 길이 여러 개 생김."""
    rnd = random.Random(seed)
    g = [[WALL] * n for _ in range(n)]
    g[1][1] = ROAD
    stack = [(1, 1)]
    while stack:
        r, c = stack[-1]
        nxt = [(r + dr, c + dc, dr, dc) for dr, dc in ((-2, 0), (2, 0), (0, -2), (0, 2))
               if 0 < r + dr < n - 1 and 0 < c + dc < n - 1 and g[r + dr][c + dc] == WALL]
        if not nxt:
            stack.pop()
            continue
        nr, nc, dr, dc = rnd.choice(nxt)
        g[r + dr // 2][c + dc // 2] = ROAD
        g[nr][nc] = ROAD
        stack.append((nr, nc))

    if loop:
        walls = [(r, c) for r in range(1, n - 1) for c in range(1, n - 1)
                 if g[r][c] == WALL and ((r % 2 == 1 and c % 2 == 0) or (r % 2 == 0 and c % 2 == 1))]
        for r, c in rnd.sample(walls, len(walls) // 10):
            g[r][c] = ROAD
    return g


def search(g, use_queue):
    """use_queue=True면 BFS(큐), False면 DFS(스택).
    반환: (방문한 칸 수, 찾은 경로 길이)"""
    n = len(g)
    start, goal = (1, 1), (n - 2, n - 2)
    parent = {start: None}
    box = deque([start])
    visited = 0
    while box:
        cur = box.popleft() if use_queue else box.pop()
        visited += 1
        if cur == goal:
            break
        r, c = cur
        for dr, dc in MOVES:
            nxt = (r + dr, c + dc)
            if g[nxt[0]][nxt[1]] == ROAD and nxt not in parent:
                parent[nxt] = cur
                box.append(nxt)
    length = 0
    cur = goal
    while cur is not None:
        length += 1
        cur = parent[cur]
    return visited, length


if __name__ == "__main__":
    print("미로 | 크기 | 길 칸 | BFS 방문 | DFS 방문 | BFS 경로 | DFS 경로")
    for loop in (False, True):
        for n in (21, 41, 81, 161):
            total = [0] * 5
            for seed in range(10):
                g = make_maze(n, seed, loop)
                roads = sum(row.count(ROAD) for row in g)
                bv, bl = search(g, True)
                dv, dl = search(g, False)
                for i, v in enumerate((roads, bv, dv, bl, dl)):
                    total[i] += v
            a = [t / 10 for t in total]
            kind = "고리" if loop else "완전"
            print(f"{kind} | {n} | {a[0]:.0f} | {a[1]:.0f} ({a[1]/a[0]*100:.1f}%) | "
                  f"{a[2]:.0f} ({a[2]/a[0]*100:.1f}%) | {a[3]:.1f} | {a[4]:.1f}")

부록 B. 면접 대비 예상 질문

Q1. BFS는 왜 최단 경로를 찾나요?
출발점에서 거리 1인 칸을 모두 본 다음 거리 2인 칸을 보는 식으로 가까운 순서대로 탐색합니다. 그래서 도착점에 처음 닿았을 때의 경로가 가장 짧은 경로입니다.
Q2. 고리 있는 미로에서 BFS가 왜 거의 모든 칸을 방문했나요?
도착점이 출발점에서 가장 먼 구석에 있어서, 도착점보다 가까운 칸을 전부 본 다음에야 도착할 수 있었기 때문입니다.
Q3. 코드에서 BFS와 DFS는 어떻게 다르게 구현했나요?
같은 함수에서 칸을 꺼내는 위치만 다릅니다. 앞에서 꺼내는 popleft()를 쓰면 큐라서 BFS, 뒤에서 꺼내는 pop()을 쓰면 스택이라서 DFS가 됩니다.
Q4. 두 알고리즘의 시간 복잡도가 같은데 결과가 왜 다른가요?
둘 다 각 칸을 최대 한 번씩 보니까 최악의 경우는 O(V+E)로 같습니다. 하지만 도착점을 찾으면 멈추기 때문에, 어떤 순서로 칸을 보느냐에 따라 실제로 방문하는 칸 수가 달라집니다.
Q5. 이 실험의 한계는 무엇인가요?
DFS가 오른쪽과 아래부터 탐색하도록 짜여 있어서 도착점 방향과 맞았습니다. 이웃 순서를 바꾸면 DFS의 결과가 달라질 수 있어서 추가 실험이 필요합니다.
