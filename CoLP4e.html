Four-Person Collaborative Projects — One per Domain

Each project assigns one module to each of four students, and the team integrates main.py together. Save the files in one folder and run python main.py. All examples use only Python's standard library.

Team contract: Agree on file names, public functions/classes, arguments, return values, units, and exception rules before coding. Do not edit teammates' files without agreement.

Project 1 · Programming — Collaborative Recursive and Iterative Calculation Library

Compute factorials using two approaches and compare the results.

Success criteria: After unit-testing each module, the integrated output must match the example. Explain normal, boundary, and exceptional inputs.

Student 1 · Recursion — recursive_calc.py
def factorial_recursive(n):
    """Return n! for a nonnegative integer."""
    if not isinstance(n, int) or n < 0:
        raise ValueError("A nonnegative integer is required")
    if n <= 1:
        return 1
    return n * factorial_recursive(n - 1)
Student 2 · Iteration — iterative_calc.py
def factorial_iterative(n):
    if not isinstance(n, int) or n < 0:
        raise ValueError("A nonnegative integer is required")
    result = 1
    for number in range(2, n + 1):
        result *= number
    return result
Student 3 · Validation — compare.py
from recursive_calc import factorial_recursive
from iterative_calc import factorial_iterative

def compare(n):
    recursive_value = factorial_recursive(n)
    iterative_value = factorial_iterative(n)
    assert recursive_value == iterative_value
    return recursive_value, iterative_value
Student 4 · Reporting — report.py
def report(n, results):
    recursive_value, iterative_value = results
    return f"{n}! = {recursive_value}, iterative result = {iterative_value}"
Team integration — main.py
from compare import compare
from report import report

if __name__ == "__main__":
    print(report(5, compare(5)))

Expected output

5! = 120, iterative result = 120

Additional testing: Each teammate should propose at least one boundary or exceptional case and record it in the team test log.

Project 2 · Data Structures — Library Checkout and Return Queue

Use a queue and stack to manage waiting requests and recent returns.

Success criteria: After unit-testing each module, the integrated output must match the example. Explain normal, boundary, and exceptional inputs.

Student 1 · Queue — queue_service.py
from collections import deque

class WaitingQueue:
    def __init__(self):
        self.items = deque()
    def enqueue(self, name):
        self.items.append(name)
    def dequeue(self):
        if not self.items:
            raise IndexError("The queue is empty")
        return self.items.popleft()
Student 2 · Stack — stack_history.py
class ReturnHistory:
    def __init__(self):
        self.items = []
    def record(self, book):
        self.items.append(book)
    def latest(self):
        if not self.items:
            raise IndexError("No return history")
        return self.items[-1]
Student 3 · Operations — library_ops.py
from queue_service import WaitingQueue
from stack_history import ReturnHistory

def demonstrate():
    waiting = WaitingQueue()
    for name in ("Aram", "Narae"):
        waiting.enqueue(name)
    history = ReturnHistory()
    history.record("Introduction to Data Structures")
    return waiting.dequeue(), history.latest()
Student 4 · Reporting — report.py
def summarize(person, book):
    return f"Processed: {person} / latest return: {book}"
Team integration — main.py
from library_ops import demonstrate
from report import summarize

if __name__ == "__main__":
    print(summarize(*demonstrate()))

Expected output

Processed: Aram / latest return: Introduction to Data Structures

Additional testing: Each teammate should propose at least one boundary or exceptional case and record it in the team test log.

Project 3 · Algorithms — School Route-Finding Library

Collaboratively implement graph representation and BFS path reconstruction.

Success criteria: After unit-testing each module, the integrated output must match the example. Explain normal, boundary, and exceptional inputs.

Student 1 · Graph — graph_data.py
def school_map():
    return {
        "Classroom": ["Hallway", "Library"],
        "Hallway": ["Classroom", "Laboratory"],
        "Library": ["Classroom", "Laboratory"],
        "Laboratory": ["Hallway", "Library"]
    }
Student 2 · Search — search_bfs.py
from collections import deque

def shortest_path(graph, start, goal):
    if start not in graph or goal not in graph:
        raise ValueError("Unknown vertex")
    queue = deque([(start, [start])])
    visited = {start}
    while queue:
        current, path = queue.popleft()
        if current == goal:
            return path
        for neighbor in graph[current]:
            if neighbor not in visited:
                visited.add(neighbor)
                queue.append((neighbor, path + [neighbor]))
    return None
Student 3 · Validation — validate.py
def validate_path(graph, path):
    if not path:
        return False
    return all(b in graph[a] for a, b in zip(path, path[1:]))
Student 4 · Reporting — report.py
def path_report(path):
    return " → ".join(path) if path else "Unreachable"
Team integration — main.py
from graph_data import school_map
from search_bfs import shortest_path
from validate import validate_path
from report import path_report

if __name__ == "__main__":
    graph = school_map()
    path = shortest_path(graph, "Classroom", "Laboratory")
    assert validate_path(graph, path)
    print(path_report(path))

Expected output

Classroom → Hallway → Laboratory

Additional testing: Each teammate should propose at least one boundary or exceptional case and record it in the team test log.

Project 4 · Computer Science Projects — Classroom Energy-Saving Library

Separate energy measurement, reduction goals, evaluation, and reporting into modules.

Success criteria: After unit-testing each module, the integrated output must match the example. Explain normal, boundary, and exceptional inputs.

Student 1 · Measurement — meter.py
def energy_usage(devices):
    """devices: (watts, hours) pairs; return energy in Wh."""
    if any(w < 0 or h < 0 for w, h in devices):
        raise ValueError("Power and time must be nonnegative")
    return sum(w * h for w, h in devices)
Student 2 · Savings — saving.py
def after_savings(usage, reduction_rate):
    if not 0 <= reduction_rate <= 1:
        raise ValueError("Reduction rate must be between 0 and 1")
    return usage * (1 - reduction_rate)
Student 3 · Evaluation — evaluation.py
def evaluate(before, after):
    if before < 0 or after < 0:
        raise ValueError("Energy usage cannot be negative")
    return "Savings achieved" if after < before else "Needs improvement"
Student 4 · Reporting — report.py
def summarize(before, after, assessment):
    return f"Before: {before:g} Wh → After: {after:g} Wh / {assessment}"
Team integration — main.py
from meter import energy_usage
from saving import after_savings
from evaluation import evaluate
from report import summarize

if __name__ == "__main__":
    before = energy_usage([(100, 3), (50, 2)])
    after = after_savings(before, 0.25)
    print(summarize(before, after, evaluate(before, after)))

Expected output

Before: 400 Wh → After: 300 Wh / Savings achieved

Additional testing: Each teammate should propose at least one boundary or exceptional case and record it in the team test log.
