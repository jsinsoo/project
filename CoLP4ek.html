1. Programming — Concept-Based Learning1. 프로그래밍 — 개념 기반 학습

Big ideas: Functions · Recursion · Modules · OOP · Recommended: 7 lessons핵심 아이디어: 함수·재귀·모듈·객체 지향 · 권장 7차시

Concept 1-1개념 1-1

Functions and Parameters함수와 매개변수

Concept: Define inputs and outputs as a contract so the same function can be reused.개념 설명: 입력과 출력을 계약으로 정의하여 같은 기능을 반복 활용한다.

Inquiry question: Does a function retain its responsibility when its input changes?탐구 질문: 입력값이 바뀌어도 함수의 책임은 유지되는가?

Learning activity: Specify a function name, arguments, and return value; test normal and boundary inputs.학습 활동: 함수 이름, 인자, 반환값을 명세하고 정상·경계 입력을 시험한다.

Assessment evidence: Explain the concept in your own words and show the code's input, processing, output, and test results.평가 증거: 개념을 자신의 말로 설명하고 코드의 입력·처리·출력과 시험 결과를 제시한다.

Concept 1-2개념 1-2

Recursion and Base Cases재귀와 종료 조건

Concept: Break a problem into smaller instances of the same structure and stop at a base case.개념 설명: 문제를 더 작은 동일 구조로 나누고 종료 조건에서 멈춘다.

Inquiry question: What can go wrong without a base case?탐구 질문: 종료 조건이 없다면 어떤 문제가 생길까?

Learning activity: Trace how recursive arguments change and how the call stack develops.학습 활동: 재귀 호출의 입력 변화와 호출 스택을 추적한다.

Assessment evidence: Explain the concept in your own words and show the code's input, processing, output, and test results.평가 증거: 개념을 자신의 말로 설명하고 코드의 입력·처리·출력과 시험 결과를 제시한다.

Concept 1-3개념 1-3

Comparing Iteration and Recursion반복과 재귀 비교

Concept: Compare iterative and recursive solutions in terms of correctness and resource use.개념 설명: 동일 문제의 반복·재귀 구현을 정확성과 자원 사용 측면에서 비교한다.

Inquiry question: When might iteration be more suitable?탐구 질문: 어떤 상황에서 반복이 더 적합할까?

Learning activity: Compare outputs and discuss recursion depth limits.학습 활동: 두 구현의 결과를 비교하고 재귀 깊이 한계를 토론한다.

Assessment evidence: Explain the concept in your own words and show the code's input, processing, output, and test results.평가 증거: 개념을 자신의 말로 설명하고 코드의 입력·처리·출력과 시험 결과를 제시한다.

Concept 1-4개념 1-4

Modules and Object-Oriented Programming모듈과 객체 지향

Concept: Encapsulate related state and behavior in classes and reuse them across files.개념 설명: 관련 상태와 기능을 클래스로 묶고 파일 단위로 재사용한다.

Inquiry question: How does renaming a public module function affect teammates' code?탐구 질문: 모듈의 공개 이름을 바꾸면 동료 코드에 어떤 영향이 생길까?

Learning activity: Practice classes, methods, import statements, and the __name__ guard.학습 활동: 클래스, 메서드, import, __name__ 보호 구문을 실습한다.

Assessment evidence: Explain the concept in your own words and show the code's input, processing, output, and test results.평가 증거: 개념을 자신의 말로 설명하고 코드의 입력·처리·출력과 시험 결과를 제시한다.

2. Data Structures — Concept-Based Learning2. 데이터 구조 — 개념 기반 학습

Big ideas: Stacks · Queues · Trees · Graphs · Recommended: 8 lessons핵심 아이디어: 스택·큐·트리·그래프 · 권장 8차시

Concept 2-1개념 2-1

Abstract Data Types and Stacks추상 자료형과 스택

Concept: Distinguish last-in, first-out behavior and the push, pop, and peek operations.개념 설명: 후입선출 구조와 push·pop·peek 연산의 의미를 구분한다.

Inquiry question: Why is a stack suitable for undo operations?탐구 질문: 실행 취소는 왜 스택과 어울릴까?

Learning activity: Implement a class that also handles empty-stack errors.학습 활동: 빈 스택 예외를 포함한 클래스를 구현한다.

Assessment evidence: Explain the concept in your own words and show the code's input, processing, output, and test results.평가 증거: 개념을 자신의 말로 설명하고 코드의 입력·처리·출력과 시험 결과를 제시한다.

Concept 2-2개념 2-2

Queues and Waiting Lines큐와 대기열

Concept: Use first-in, first-out behavior to preserve processing order.개념 설명: 선입선출 구조를 이용해 처리 순서를 보장한다.

Inquiry question: Why can deque be preferable to list.pop(0)?탐구 질문: 리스트 pop(0)보다 deque가 유리한 이유는?

Learning activity: Test enqueue, dequeue, and empty-queue behavior.학습 활동: enqueue·dequeue와 빈 큐를 검증한다.

Assessment evidence: Explain the concept in your own words and show the code's input, processing, output, and test results.평가 증거: 개념을 자신의 말로 설명하고 코드의 입력·처리·출력과 시험 결과를 제시한다.

Concept 2-3개념 2-3

Trees and Hierarchical Relationships트리와 계층 관계

Concept: Represent hierarchies using parents, children, roots, and leaves.개념 설명: 부모·자식·루트·잎 노드로 계층 구조를 표현한다.

Inquiry question: Why is a graph with a cycle not a tree?탐구 질문: 순환이 있는 그래프는 언제 트리가 될 수 없을까?

Learning activity: Build child relationships from a parent list.학습 활동: 부모 목록을 이용해 자식 관계를 생성한다.

Assessment evidence: Explain the concept in your own words and show the code's input, processing, output, and test results.평가 증거: 개념을 자신의 말로 설명하고 코드의 입력·처리·출력과 시험 결과를 제시한다.

Concept 2-4개념 2-4

Graphs and Traversal그래프와 탐색

Concept: Represent relationships with vertices, edges, adjacency lists, and visited sets.개념 설명: 정점·간선, 인접 리스트, 방문 집합을 이용해 관계를 표현한다.

Inquiry question: Why do BFS and DFS visit vertices in different orders?탐구 질문: BFS와 DFS는 방문 순서가 왜 다른가?

Learning activity: Explore traversal results using an adjacency list and queue.학습 활동: 인접 리스트와 큐를 이용해 탐색 결과를 확인한다.

Assessment evidence: Explain the concept in your own words and show the code's input, processing, output, and test results.평가 증거: 개념을 자신의 말로 설명하고 코드의 입력·처리·출력과 시험 결과를 제시한다.

3. Algorithms — Concept-Based Learning3. 알고리즘 — 개념 기반 학습

Big ideas: Exhaustive search · Pruning · Divide and conquer · Dynamic programming · Complexity · Recommended: 12 lessons핵심 아이디어: 완전 탐색·가지치기·분할정복·동적계획·복잡도 · 권장 12차시

Concept 3-1개념 3-1

State Spaces and Exhaustive Search상태 공간과 완전 탐색

Concept: Generate every possible candidate and check whether it satisfies the conditions.개념 설명: 가능한 후보를 빠짐없이 생성해 조건을 확인한다.

Inquiry question: How does the number of operations grow with the number of candidates?탐구 질문: 후보 수가 늘면 연산량은 어떻게 달라질까?

Learning activity: Enumerate all subsets for a small input.학습 활동: 작은 입력에서 모든 부분집합을 열거한다.

Assessment evidence: Explain the concept in your own words and show the code's input, processing, output, and test results.평가 증거: 개념을 자신의 말로 설명하고 코드의 입력·처리·출력과 시험 결과를 제시한다.

Concept 3-2개념 3-2

Backtracking and Pruning백트래킹과 가지치기

Concept: Stop exploring branches that cannot lead to valid solutions, without losing correct answers.개념 설명: 조건에 어긋난 경로를 중단하되 정답은 누락하지 않는다.

Inquiry question: What makes a pruning rule safe?탐구 질문: 어떤 가지치기 조건이 안전한가?

Learning activity: Compare search counts using a partial-sum bound for positive integers.학습 활동: 양수 목록의 부분합 상한을 활용해 탐색 횟수를 비교한다.

Assessment evidence: Explain the concept in your own words and show the code's input, processing, output, and test results.평가 증거: 개념을 자신의 말로 설명하고 코드의 입력·처리·출력과 시험 결과를 제시한다.

Concept 3-3개념 3-3

Divide and Conquer and Sorting분할정복과 정렬

Concept: Divide a problem, solve its parts, and combine their results.개념 설명: 문제를 분할·해결·결합하여 전체 결과를 얻는다.

Inquiry question: Why is merge sort a divide-and-conquer algorithm?탐구 질문: 병합 정렬은 왜 분할정복인가?

Learning activity: Verify the sorted order and preservation of element counts.학습 활동: 정렬 결과와 원소 개수를 시험한다.

Assessment evidence: Explain the concept in your own words and show the code's input, processing, output, and test results.평가 증거: 개념을 자신의 말로 설명하고 코드의 입력·처리·출력과 시험 결과를 제시한다.

Concept 3-4개념 3-4

Dynamic Programming and Big-O동적계획법과 빅오

Concept: Store overlapping subproblem results and analyze operation growth as input size increases.개념 설명: 중복 부분 문제를 저장하고 입력 크기별 연산량을 분석한다.

Inquiry question: How does memoization reduce repeated computation?탐구 질문: 메모이제이션이 중복 계산을 어떻게 줄일까?

Learning activity: Compare Fibonacci implementations and infer time complexity.학습 활동: 피보나치 결과를 비교하고 시간 복잡도를 추론한다.

Assessment evidence: Explain the concept in your own words and show the code's input, processing, output, and test results.평가 증거: 개념을 자신의 말로 설명하고 코드의 입력·처리·출력과 시험 결과를 제시한다.

4. Computer Science Projects — Concept-Based Learning4. 정보과학 프로젝트 — 개념 기반 학습

Big ideas: Problem definition · Interface contracts · Integration · Validation · Recommended: 7 lessons핵심 아이디어: 문제 정의·협업 계약·통합·검증 · 권장 7차시

Concept 4-1개념 4-1

Problem Identification and Requirements문제 발견과 요구 분석

Concept: Turn a real-world difficulty into a clear description of users, inputs, outputs, and constraints.개념 설명: 실생활의 불편을 사용자·입력·출력·제약으로 구체화한다.

Inquiry question: How should we define the boundaries of the problem?탐구 질문: 문제의 범위를 어디까지 제한할 것인가?

Learning activity: Write user stories and success criteria.학습 활동: 사용자 이야기와 성공 조건을 작성한다.

Assessment evidence: Explain the concept in your own words and show the code's input, processing, output, and test results.평가 증거: 개념을 자신의 말로 설명하고 코드의 입력·처리·출력과 시험 결과를 제시한다.

Concept 4-2개념 4-2

Role Assignment and Interfaces역할 분담과 인터페이스

Concept: Four teammates agree in advance on files, function names, arguments, return types, and exception policies.개념 설명: 4명이 파일·함수명·인자·반환형·예외 정책을 먼저 합의한다.

Inquiry question: Why can teammates integrate modules without knowing their internal implementation?탐구 질문: 팀원이 서로의 구현을 몰라도 연결 가능한 이유는?

Learning activity: Write a shared interface contract and assign responsibility for each file.학습 활동: 공유 계약서를 작성하고 파일별 책임을 구분한다.

Assessment evidence: Explain the concept in your own words and show the code's input, processing, output, and test results.평가 증거: 개념을 자신의 말로 설명하고 코드의 입력·처리·출력과 시험 결과를 제시한다.

Concept 4-3개념 4-3

Library Integration and Code Review라이브러리 통합과 검토

Concept: Import individually developed modules and connect them through a shared main.py.개념 설명: 각자 만든 모듈을 import하고 공동 main.py에서 연결한다.

Inquiry question: Why can independently working modules fail when integrated?탐구 질문: 독립 실행은 성공했는데 통합이 실패하는 이유는?

Learning activity: Run module tests, integration tests, and peer code reviews.학습 활동: 모듈별 시험 뒤 통합 시험과 코드 검토를 진행한다.

Assessment evidence: Explain the concept in your own words and show the code's input, processing, output, and test results.평가 증거: 개념을 자신의 말로 설명하고 코드의 입력·처리·출력과 시험 결과를 제시한다.

Concept 4-4개념 4-4

Validation, Improvement, and Sharing검증·개선·공유

Concept: Reproduce defects with normal, boundary, and exceptional cases and document improvements.개념 설명: 정상·경계·예외 사례로 오류를 재현하고 개선 내용을 기록한다.

Inquiry question: What should a reproducible bug report include?탐구 질문: 재현 가능한 오류 보고서는 무엇을 포함해야 할까?

def factorial_recursive(n):
    """Return n! for a nonnegative integer."""
    if not isinstance(n, int) or n < 0:
        raise ValueError("A nonnegative integer is required")
    if n <= 1:
        return 1
    return n * factorial_recursive(n - 1)
Student 2 · Iteration — iterative_calc.py학생 2 · 반복 담당 — iterative_calc.py
def factorial_iterative(n):
    if not isinstance(n, int) or n < 0:
        raise ValueError("A nonnegative integer is required")
    result = 1
    for number in range(2, n + 1):
        result *= number
    return result
Student 3 · Validation — compare.py학생 3 · 검증 담당 — compare.py
from recursive_calc import factorial_recursive
from iterative_calc import factorial_iterative

def compare(n):
    recursive_value = factorial_recursive(n)
    iterative_value = factorial_iterative(n)
    assert recursive_value == iterative_value
    return recursive_value, iterative_value

from collections import deque

class WaitingQueue:
    def __init__(self):
        self.items = deque()
    def enqueue(self, name):
        self.items.append(name)
    def dequeue(self):
        if not self.items:
            raise IndexError("The queue is empty")
        return self.items.popleft()
Student 2 · Stack — stack_history.py학생 2 · 스택 담당 — stack_history.py
class ReturnHistory:
    def __init__(self):
        self.items = []
    def record(self, book):
        self.items.append(book)
    def latest(self):
        if not self.items:
            raise IndexError("No return history")
        return self.items[-1]

from collections import deque

def shortest_path(graph, start, goal):
    if start not in graph or goal not in graph:
        raise ValueError("Unknown vertex")
    queue = deque([(start, [start])])
    visited = {start}
    while queue:
        current, path = queue.popleft()
        if current == goal:
            return path
        for neighbor in graph[current]:
            if neighbor not in visited:
                visited.add(neighbor)
                queue.append((neighbor, path + [neighbor]))
    return None
Student 3 · Validation — validate.py학생 3 · 검증 담당 — validate.py
def validate_path(graph, path):
    if not path:
        return False
    return all(b in graph[a] for a, b in zip(path, path[1:]))

def energy_usage(devices):
    """devices: (watts, hours) pairs; return energy in Wh."""
    if any(w < 0 or h < 0 for w, h in devices):
        raise ValueError("Power and time must be nonnegative")
    return sum(w * h for w, h in devices)
Student 2 · Savings — saving.py학생 2 · 절감 계산 담당 — saving.py
def after_savings(usage, reduction_rate):
    if not 0 <= reduction_rate <= 1:
        raise ValueError("Reduction rate must be between 0 and 1")
    return usage * (1 - reduction_rate)
Student 3 · Evaluation — evaluation.py학생 3 · 평가 담당 — evaluation.py
def evaluate(before, after):
    if before < 0 or after < 0:
        raise ValueError("Energy usage cannot be negative")
    return "Savings achieved" if after < before else "Needs improvement"
